              SECTION 4: BALL PHYSICS (class Ball)
═══════════════════════════════════════════════════════════

The ball is a PHYSICS OBJECT, not just a moving square:

  TRAIL SYSTEM:
  - Store last 12 positions in a deque
  - Each past position rendered as a progressively smaller,
    more transparent circle
  - Trail colors cycle through ball's current color hue
  - Trail stretches/compresses based on ball speed (motion blur)

  PHYSICS:
  - dx, dy components (floating point for sub-pixel precision)
  - On wall bounce (top/bottom): dy *= -1 with 2% randomness
    added to prevent infinite horizontal loops
  - On paddle hit: 
      * Compute hit_position = (ball.y - paddle.y) / paddle_height
      * Map hit_position (-1 to 1) → bounce angle (-60° to 60°)
      * Preserve current speed magnitude, apply new angle
      * Speed increases by BALL_SPEED_INC per paddle hit
      * Speed capped at BALL_MAX_SPEED
  - Ball starts each round from center with random angle between
    -30° and 30° (never straight horizontal)

  SPIN SYSTEM:
  - If paddle is moving when it hits ball, add spin
  - spin value (float) affects dy slightly each frame
  - spin decays by 5% each frame toward 0
  - Spinning ball has a slight arc trajectory (realistic)

  MULTI-BALL MODE:
  - When MULTI_BALL power-up active, spawn 2 extra balls
  - Each extra ball inherits current speed but random direction
  - Points only scored by original ball; extras are chaos agents
  - Extra balls disappear after power-up duration ends
  - Extra balls rendered in different colors (orange, green)

  GHOST BALL MODE:
  - When GHOST power-up active for a player, their paddle 
    becomes semi-transparent AND the ball passes through 
    the opponent's paddle for 3 seconds
  - Ball rendered with dashed/dotted outline during ghost mode

  VISUAL FX ON SCORE:
  - When ball passes a paddle wall, trigger SCREEN FLASH:
      * Flash screen border the scoring player's color
      * Rapidly fade out over 12 frames
  - Camera shake effect: offset all turtle drawings by
    random(−8, 8) on x and y for 8 frames, then return to 0

Build a TRUE AI, not just "follow the ball" logic:

  DIFFICULTY LEVELS:
  ┌──────────┬──────────┬────────────────┬───────────────────┐
  │ Level    │ Speed    │ Reaction Delay │ Prediction Error  │
  ├──────────┼──────────┼────────────────┼───────────────────┤
  │ EASY     │ 3 px/f   │ 350ms lag      │ ±60px random      │
  │ MEDIUM   │ 5 px/f   │ 180ms lag      │ ±25px random      │
  │ HARD     │ 7 px/f   │  60ms lag      │ ±8px random       │
  │ PERFECT  │ 9 px/f   │   0ms lag      │ 0px (unbeatable)  │
  └──────────┴──────────┴────────────────┴───────────────────┘

  PREDICTION ENGINE (HARD + PERFECT):
  - AI does NOT just follow ball.y
  - It calculates WHERE the ball will be when it reaches 
    the AI's x-position using physics simulation:
      1. Copy ball's current x, y, dx, dy
      2. Step simulation forward until x == paddle_x
      3. Account for wall bounces during simulation
      4. Target that predicted y (with difficulty error added)
  - Recalculates prediction every time ball changes direction

  ADAPTIVE AI (MEDIUM+):
  - Tracks player's last 10 hit positions on paddle
  - Detects if player always aims high or low → compensates
  - If AI is winning by 4+ points: introduces fake hesitation
    (mimics difficulty to keep game interesting)
  - If AI is losing by 4+ points: reduces error slightly

  RETURN STRATEGY:
  - Instead of always centering the ball return:
      * If AI is ahead: aim for safe center returns
      * If AI is behind: aim for sharp-angle returns 
        (hit edge of own paddle = extreme angle)
  - AI deliberately targets opponent's moving direction 
    (forces them to reverse, harder to reach)

  SETTINGS PAGE:
  - Allow choosing AI difficulty before game start
  - Animated difficulty selector with visual preview of AI speed

═══════════════════════════════════════════════════════════
         SECTION 18: GAME LOOP ARCHITECTURE
              (class GameEngine)
═══════════════════════════════════════════════════════════

  The game loop must be PRECISE and FRAME-RATE CONTROLLED:

  def game_loop(self):
      while self.running:
          frame_start = time.perf_counter()
          
          # 1. Process input (key states, not key events)
          self.process_input()
          
          # 2. Update game state
          self.update_physics()        # ball, paddles
          self.update_particles()      # age + move particles
          self.update_powerups()       # spawn timer, duration
          self.update_background()     # stars, shooting stars
          self.update_ui_animations()  # score bounce, glows
          self.check_collisions()      # paddle, wall, powerup
          self.check_win_condition()
          
          # 3. Render everything
          self.screen.tracer(0)
          self.clear_all_turtles()
          self.render_background()
          self.render_powerups()
          self.render_particles()
          self.render_paddles()
          self.render_ball()
          self.render_ui()
          self.screen.update()
          
          # 4. Frame rate control (cap at FPS_TARGET)
          elapsed = time.perf_counter() - frame_start
          sleep_time = max(0, (1/FPS_TARGET) - elapsed)
          time.sleep(sleep_time)
          
          # 5. Calculate actual FPS
          self.actual_fps = 1 / max(elapsed, 0.001)

  KEY STATE SYSTEM:
  - Use a dictionary: keys_held = {} 
  - screen.onkeypress(lambda: keys_held.__setitem__('w', True), 'w')
  - screen.onkeyrelease(lambda: keys_held.pop('w', None), 'w')
  - Check keys_held in process_input() each frame
  - This prevents key-repeat lag and allows simultaneous key presses
